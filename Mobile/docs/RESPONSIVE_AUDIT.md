# Аудит адаптивности

## До изменения

GTK4: app.py строил окно 360×800, --size выбирал три стартовых размера. FlowBox имел 2–3 столбца; автоматического выбора режима не было. Размер окна был начальным запросом, не запретом resize. Уже работали прокрутка сетки/дашборда, эллипсис подписей, минимум кнопок 44 px, GTK масштабирование.

Проблемы: часы/обои/поиск вне прокрутки занимали высоту при повороте и OSK; горизонтальный Box дока ограничивался четырьмя записями; дашборд имел всегда два столбца; длинные подписи обычных кнопок не переносились; часы/заголовок использовали px, независимо от системного шрифта.

## Реализовано

- ResponsiveBin получает фактическую allocation GTK и вызывает чистую политику layout.choose. Нет таймера определения размера, имени устройства или физических пикселей. --size остался только стартовым запросом для тестов.
- Режимы по ширине: compact <380, standard <480, expanded <720, tablet ≥720. Отступы 8/12/16 px, в низком окне (<480) интервалы сокращаются и декоративные часы скрываются; время остаётся в системной панели Phosh.
- Сетка: до 8 столбцов, бюджет ячейки 80×font_scale плюс 8 px между ячейками. GTK FlowBox может уменьшить число дополнительно по реальным minimum sizes. Минимум один столбец позволяет корректно учитывать крупный шрифт. Расчётная цель при обычном шрифте: 320 → 3, 360/393/412 → 4, 540 → 5, 800 → 8.
- Домашняя страница прокручивается целиком. GtkViewport scroll-to-focus включён явно. Док находится в конце страницы, переносится на строки, не имеет ограничения в четыре записи и не накладывается на системные панели. Доступ к доку может требовать прокрутки — сознательный выбор для низких окон.
- Карточки состояния и кнопки дашборда: 1–4 столбца, бюджет 160×font_scale. Текст кнопок переносится, подписи приложений сокращаются. Полное имя доступно как tooltip дока; запуск не требует hover. Карточки переносят и слова без пробелов.
- Размеры текста часов и заголовка в em; Pango font size уменьшает число колонок при увеличении шрифта. GTK и Wayland отвечают за HiDPI/дробный масштаб, приложение не меняет compositor scale.
- Смена ориентации использует тот же allocation path, перезапуск не нужен. Глобальных жестов нет, прежний swipe только в заголовке сохранён.

## Проверка и пределы доказательств

Расчёты проверены для шести заданных размеров, ширин 240–800 и font scale 1/1.5/2. Это unit tests, не визуальные результаты. GUI smoke проверяет allocation, minimum width, ширину поиска/сетки/дока. Дополнительные GTK measurement tests проверяют длинную подпись с удвоенным шрифтом и 16 элементов дока; при отсутствии display они явно пропускаются.

В этой среде GUI недоступен: реальная раскладка, fractional scale, touch, OSK, поворот без перезапуска и крупный системный шрифт требуют внешнего теста. Пороги выбраны по бюджету размеров, а не по визуальной калибровке телефона. Не обещается размещение произвольно большого шрифта на экране меньше минимальных touch targets. Native Phosh может менять доступную область иначе, чем настольный compositor; проверить на устройстве обязательно.
