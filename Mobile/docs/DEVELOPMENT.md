# Разработка и сборка

CachyOS: системные `python`, `python-gobject`, `gtk4`, `make`; необязательно CLI интеграций. Зависимостей pip нет.

```sh
make check
make run
make smoke
```

Smoke требует доступного графического дисплея и сессионной D-Bus. В CI используется Xvfb. `--smoke-test` не включает Wi-Fi, Bluetooth, не меняет звук или яркость: только строит окно, читает состояния и закрывается. Не используйте код возврата старых версий GTK как единственный признак: в логе должна быть строка `SMOKE OK`.

Воспроизводимая подготовка исходников (из чистого Git HEAD):

```sh
./scripts/build-source.sh
sha256sum build/alpine/hyprstack-mobile-0.1.0.tar.gz
```

git archive сохраняет timestamp коммита, gzip -n исключает время упаковки. Получаются локальный tarball и APKBUILD с SHA512. Скопируйте `build/alpine/` в Alpine/pmOS build environment с `alpine-sdk`, обычным пользователем группы abuild выполните `abuild -r` после настройки ключа по документации Alpine. Не запускайте сборку root. Пакет `noarch` содержит Python, ABI-бинарных модулей проекта нет; системные GTK/GI на ARM64 ставит apk. Этот рецепт пока не проходил abuild на ARM64 и не является готовым подписанным APK.

CI: compileall, unit tests, sh -n, GTK smoke Ubuntu/Xvfb, unit tests Alpine 3.23 x86_64. ARM64 job и аппаратные тесты пока отсутствуют. Не выдавайте зелёный x86_64 CI за проверку телефона.

## Воспроизведение на CachyOS вне ограниченного агента

Из терминала текущей графической сессии, обычным пользователем:

```sh
sudo pacman -S --needed python python-gobject gtk4 make
cd /home/w1nq/hyprstack-src/personal/Mobile
printf '%s\n' "$WAYLAND_DISPLAY" "$XDG_RUNTIME_DIR"
make check
GDK_BACKEND=wayland ./scripts/run.sh --size 360x800
GDK_BACKEND=wayland ./scripts/run.sh --smoke-test --size 360x800
```

Не запускайте через sudo и не подставляйте чужой XDG_RUNTIME_DIR. При отсутствии display запускайте из терминала рабочего стола, а не из SSH без графического окружения. Smoke успешен только при коде 0 и строке `SMOKE OK`. Он читает системные состояния, но не переключает оборудование.

1080×2400 при compositor scale 3 соответствует 360×800, при scale 2 — 540×1200 логических пикселей. Панели Phosh дополнительно сокращают доступную область. Проверяйте также `--size 540x1200` и `--size 320x640` (сокращённая область). Это размер окна в логических пикселях, а не эмуляция телефона; не умножайте одновременно размер окна и compositor scale. Реальную плотность/OSK проверяйте на телефоне. Проверка всех размеров в этой среде заблокирована отсутствием дисплея.

Ручная приёмка: часы/дата; поиск по части названия и очистка; запуск приложения; долгое нажатие → добавить/удалить избранное; четыре длинных названия в доке; переходы на дашборд; светлая/тёмная тема; ошибки отсутствующих служб; закрытие окна. Убедитесь, что контент не расширяет окно за доступную ширину. Тестировать кнопки изменения Wi-Fi/звука следует отдельно, осознанно: smoke этого не делает.

## APK на отдельной Alpine aarch64 машине

В этой среде abuild/QEMU отсутствуют, Docker socket недоступен. Используйте Alpine 3.23 aarch64 VM/машину или отдельную среду сборки pmOS. Не меняйте систему телефона ради сборки.

На CachyOS из чистого коммита: `./scripts/build-source.sh`. Перенесите оба файла из `build/alpine/` в каталог сборки на Alpine. Затем:

```sh
# Администратор тестовой Alpine машины:
sudo apk add alpine-sdk python3 py3-gobject3 gtk4.0 make
sudo addgroup "$USER" abuild
# Выйти и войти заново для применения группы.
# Обычный пользователь, в каталоге с APKBUILD и tar.gz:
uname -m                     # должно быть aarch64
abuild-keygen -a -i
abuild -r
```

Результат искать в `~/packages/`. Пакет noarch, поскольку содержит Python; это не доказательство работы GI/GTK на ARM64. Сохраните полный вывод abuild, версии пакетов и отдельно проверьте установку/удаление APK на тестовой системе. Эти команды подготовлены, но в текущей среде не выполнялись.

## Responsive-проверка

Обычный запуск `./scripts/run.sh` автоматически реагирует на allocation окна; --size не нужен для установки. Политика описана в RESPONSIVE_AUDIT.md.

```sh
./scripts/test-responsive.sh
# GTK measurement tests в графической сессии:
make check
# Ручная проверка:
./scripts/run.sh --size 393x873
./scripts/run.sh --size 800x360
```

GUI script проверяет все шесть размеров последовательно, прекращает работу при ошибке. Во время ручного теста изменяйте размер одного и того же окна, добавьте более четырёх избранных, используйте длинные названия, увеличьте системный шрифт, откройте OSK. Подписи не должны накладываться, поиск должен прокручиваться к фокусу. Проверьте оба направления смены ориентации, scale 2/3 и доступные дробные значения compositor. Размер окна может быть переопределён оконным менеджером; smoke печатает фактическую allocation.
